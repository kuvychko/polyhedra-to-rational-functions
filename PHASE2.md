# Phase 2 plan: explanation and exhibition

The working plan for `PROGRAM.md` §14–15. Decisions are recorded in
`docs/decisions/0006-phase2-workflow.md`.

Two tracks run in parallel and meet in `catalog/pieces.yaml`. The **per-piece checklist** (print,
photograph, upload, link) is generated from the catalog by `scripts/catalog_status.py`, not kept
by hand here.

## Shared

- [ ] **S1 Catalog:** `catalog/pieces.yaml` schema, the four printed pieces, the remaining baseline
  pieces and the new candidates. `scripts/catalog_status.py` writes the checklist.

## Track A: website (Claude builds, owner reviews)

- [x] **A1 Scaffold:**
  - MkDocs Material configured as in complexplorer (`mkdocs.yml`, strict build, MathJax);
  - a `docs` dependency group;
  - a CI build job (no deploy).
  - The site source is `docs/`. Internal records (decisions, notes) are either published as part
    of the research path or excluded deliberately.
- [x] **A2 Research path:**
  - the narrative;
  - a recipe page with the worked example;
  - E001–E004 summaries with their figures;
  - limitations, open questions, "Reproduce".
- [x] **A3 Exhibition path:**
  - a home page with a strong photo and two entry points ("the objects", "the question");
  - the gallery and per-piece pages generated from the catalog: recipe, function, coordinated
    views, photo, print status, Printables link;
  - one complete worked example: solid → zeros and poles → plane → sphere → relief → print →
    photo.
- [x] **A4 Assets:** a script precomputes the site's renders (matched cameras and palettes,
  order-tuned display labelled as tuned), separate from the site build. The primary animation
  (sphere → relief → neutral) is optional, with a static alternative.
- [ ] **A5 Validation:**
  - [x] strict build with no broken links or anchors (anchors are now validated too);
  - [x] subpath-safe links, alt text and local images: `scripts/a5_check_site.py`, run in CI;
  - [x] claims checked against the experiment records: `tests/test_site_claims.py`. It caught
    two wrong figures, now corrected;
  - [x] reduced motion: the site has no animations; the optional A4 animation stays out until it
    has a static alternative;
  - [ ] phone-width layout seen in a browser. The automated browser could not emulate a phone
    viewport. The layout is responsive by construction (Material, auto-fill grids, scrolling
    tables), but nobody has looked at it yet;
  - [ ] owner read-through of every page.
- [x] **A6 Release workflow:** a manual-dispatch deploy (`.github/workflows/docs.yml`,
  `mkdocs gh-deploy`). First run at release, 2026-10-04.

## Track B: physical (Claude screens and exports, owner prints and uploads)

- [ ] **B1 Printability screen:** mesh each candidate with the order-tuned display, at 80 and
  130 mm. Report:
  - closure;
  - extent, waist and volume;
  - the closest zero–pole separation in mm;
  - renders.

  The owner picks pieces and sizes from the screening sheet.
- [ ] **B2 Exports:**
  - **baseline pieces:** the original STLs, both sizes, hashed into the catalog;
  - **new pieces:** generated by a script, both sizes, with a manifest;
  - STLs stay out of git.
- [ ] **B2b Cuts (decision 0007):** `scripts/p002_cut_proposals.py` proposes three planes per
  piece. The owner approves one in the catalog (`cut: {normal, approved: true}`), and
  `b2_export_stls.py` writes the cut halves in print pose.
- [ ] **B3 Owner loop, per piece:** print, photograph, then upload a Printables listing (both
  sizes, CC BY 4.0, a link to the site). Record the size, date, photo paths and URL in the
  catalog.
